# SAGA Capability 구현 결과와 학습 기록

## 추가 요구사항 구현 및 재검증 (2026년 10월 19일)

요청 ID를 영속화하여 **타임아웃을 실행 종료로 오해하지 않는 재시도 계약**을 구현했다. 같은 `operation_id`는 원래 인증서·업무·정규화 호출에 결합된다. 승인 전에는 원래 grant를 회복하고, 실행 중에는 상태만 반환하며, 완료 뒤에는 같은 트랜잭션에 저장한 결과 영수증을 반환한다. 이미 사용한 토큰의 admission 성공을 재전송하지 않으므로 중복 dispatch가 발생하지 않는다. 원래 효과가 있었지만 finish가 커밋되지 않은 경우는 여전히 불확실한 실행 중으로 남기며 자동 재실행하지 않는다.

독립 검토에서 같은 ID의 동시 ready 재시도 중 거절된 쪽이 `retry_safe=true`를 반환하는 오류, SDK·C++·Provider의 요청 ID 문법 차이, 상태를 가진 사용자 어댑터가 두 번 정규화되어 작업 결합과 실제 capability가 달라질 수 있는 오류를 발견해 수정했다. 실제 CLI 경쟁, 응답 유실, 늦은 완료, 커밋 전후 프로세스 종료로 검증했다.

호환 양식은 canonical, OpenAI Chat Completions/Responses, Anthropic, Gemini, MCP의 단일 완료 호출이다. 호출 ID를 보존한 결과 매핑과 SDK `execute_tool_call()`을 제공한다. 전체 대화·스트리밍·모델 API 호출은 호스트의 책임이다. 경로는 JSON null·빈 값·bytes·NUL·잘못된 Unicode를 파일 접근 전에 거절하며, 파일 **내용**의 NUL은 그대로 보존한다.

병렬성과 격리는 별개로 실험했다. 현재 이미 호출마다 fresh executor를 만드는 cycling이며, 동일 agent의 직렬화는 Provider의 정책상 gate다. 독립 등록 agent의 HTTP 처리가 실제 겹침을 확인했다. fork·exec·sandbox·전체 mTLS 호출의 반복 측정, 큰 부모 메모리와 실행 간 변동, pool/lane의 보장 변화는 [트레이드오프 보고서](concurrency-tradeoffs.ko.md)와 원시 JSON에 기록했다. fork 자체가 항상 지배적이거나 항상 무시할 수 있다는 일반화는 근거가 없다.

일반 Release와 Clang UBSan에서 각각 **545개 Python 테스트를 제외 없이 통과**했고 CTest도 각각 **2/2** 통과했다. 패키지·설치 검증과 상세 범위는 [검증 기록](verification.md)을 기준으로 한다. 이 결과는 무결함 증명이 아니다. 아래 기록은 이전 구현 단계의 결과다.

배포 검사에서도 기본 공유 라이브러리 설치 후 CLI가 자신의 라이브러리를 찾지 못하는 결함을 재현했다. 설치 실행 파일 기준의 상대 RUNPATH로 수정하고, 원래 build·설치 경로를 옮긴 뒤 환경 변수 없이 CLI·fresh executor·설치 CMake 소비자가 작동함을 확인했다. README·문서·예제·원시 실험 JSON을 소스 배포에 포함하고 인증서·DB·실행 산출물은 제외했다.

## 2026년 10월 19일 보완

초기 92개 테스트 통과 뒤 더 엄격한 장애 재현에서 추가 결함이 발견됐다. 테스트 통과를 무결함의 근거로 해석할 수는 없다. 이번 추가 검증은 실제 TCP/TLS 지연, 잘린 HTTP 응답, 잘못된 UTF-8, 로그 저장·잠금 장애, 프로세스의 커밋 전후 강제 종료를 대상으로 했다.

- TLS handshake를 accept 루프에서 처리해 인증하지 않은 연결 하나가 정상 요청을 막던 문제를 수정했다. 제한된 작업 스레드에서 처리하고, 헤더·본문에는 누적 시간 제한을 적용한다.
- 용량 거절 로그가 DB 잠금 때문에 accept 루프를 다시 막던 문제를 수정했다. 비대기 연결 설정을 SQLite 초기화 전부터 적용하고, stderr가 끊겨도 오류 처리 자체가 서버를 종료하지 않게 했다.
- HTTP Content-Length와 실제 본문이 달라도 성공 처리하던 파서를 수정했다. 상태줄·헤더·길이·중간 응답을 확인하고, 잘리거나 모순된 응답은 실패로 기록한다.
- SDK를 바이트 단위로 수집하도록 바꿔 잘못된 출력이 앞선 영수증을 지우지 않게 했다. 파이프 종료 대기·로그 잠금 대기를 제한하고, 로그 저장 실패·사용자 중단에도 관측한 영수증을 보존한다.
- 낮은 파일 크기 제한을 상속한 C++ 호스트가 실행 이미지 준비 중 SIGXFSZ로 종료되던 문제는 쓰기 전 제한 검사로 거절한다.
- SQLite 무한대가 JSON null로 조용히 변환되어 성공 처리되던 문제는 명시적으로 실패시킨다. 정상 NULL과 유한 숫자는 구분해 보존한다.

파일 잠금 대기에는 배치 전체가 공유하는 0.5초 한도가 추가된다. SDK의 timeout은 subprocess 처리 한도이며 로그 I/O까지 포함한 절대 완료 시한을 뜻하지 않는다. 저장장치 장애·프로세스 crash 동안의 JSONL 기록 원자성까지 보장하지 않는다. 최종 수치와 재현 명령은 [verification.md](verification.md)를 기준으로 한다.

1. **필요 자원 직접 요청:** SDK `request_resource()`가 정확한 업무·도구·자원·인자를 전달하면 C++ 워커가 PROVIDER에 매번 새 권한을 요청한다. 상태 조회와 명확한 세대 충돌만 제한적으로 재시도하고, 부작용 가능성이 있는 승인 요청은 자동 반복하지 않는다.
2. **위임 회수:** 명시적인 `revoke(expected_epoch)`가 새 토큰 없이 기존 권한을 회수한다. 서명 자체는 여전히 검증되지만, 현재 세대·토큰·상태를 검사하는 온라인 admission은 거절한다. 실행 중인 권한을 취소했다고 주장하지 않으며 `execution_busy`로 회수를 거절한다.
3. **메모리 상속 제거:** fork만으로는 부모 환경 문자열과 힙이 자식에 남는 것을 재현했다. 이제 봉인된 내장 실행 이미지를 `execveat`한 뒤 핸들러를 실행한다. 부모 메모리·이전 호출·인증정보는 복사한 채 실행하지 않고, 현재 capability만 별도 봉인 입력으로 전달한다. 물리 메모리 소거와 이미 공개된 모델 지식 삭제는 별개다.
4. **실패 기록:** 인증·정책·파싱·TLS·실행·완료 실패를 고정 오류 코드와 호출/요청 ID로 추적한다. PROVIDER 실패 기록은 롤백과 분리해 영속화하고, SDK는 설정된 0600 실패 JSONL에 접속 장애까지 기록한다. 토큰과 민감한 본문은 기록하지 않는다. 배치가 중간에 끊겨도 앞선 완료 영수증과 실패 로그를 보존한다.

현재 검증 명령과 결과는 [verification.md](verification.md), 호출·회수·로그 사용법은 [integration.md](integration.md)에 기록한다. 아래 결과는 초기 구현 당시 기록이다.

## 초기 구현 결과 (2026년 10월 13일)

Python PROVIDER, C++20 라이브러리와 워커, Python 에이전트 연결 SDK를
완성했다. 각 호출은 등록된 업무·기능·자원·인자를 담은 별도 토큰으로
실행된다. 에이전트 인증은 실제 mTLS 인증서에서 결정하며, 자연어 이름이나
모델이 주장하는 신원은 인증에 참여하지 않는다.

권한 교체의 효력 경계는 PROVIDER 데이터베이스의 커밋이다. 기존 토큰 회수와
다음 세대 발행이 함께 공개되며, 새 토큰이 응답으로 나가기 전에 기존 토큰은
새 실행을 시작할 수 없게 된다. 실행 중에는 교체 자체를 거절한다. 따라서
워커가 이전 작업을 취소하거나 이미 발생한 효과를 되돌릴 필요가 없다.

전체 Python 테스트 48개와 C++ CTest 2개가 통과했다. Clang UBSan에서도
동일한 검증이 통과했다. 실제 커널, 외부 Chinook 데이터베이스, TLS 통신,
다섯 가지 호출 양식과 설치 후 라이브러리 사용을 검증했다. 자세한 근거는
[verification.md](verification.md)에 있다.

## 트레이드오프와 통찰

1. **인증과 권한은 서로 다른 문제다.** 인증서가 맞다는 사실은 에이전트의
   신원만 증명한다. 현재 업무에 필요한 함수와 자원은 별도 정책과 토큰으로
   정해야 한다. 이름을 알아맞히는 기능을 추가해도 인증의 근거가 되지 않는다.

2. **회수는 서명을 지우는 일이 아니다.** 예전 토큰의 서명은 회수 뒤에도
   수학적으로 유효하다. 실행 직전 PROVIDER가 현재 세대와 사용 상태를 검사해야
   즉시 회수를 구현할 수 있다. 대신 모든 실행이 PROVIDER 가용성에 의존한다.

3. **원자성은 권한 상태를 소유한 곳에서 다룬다.** 워커는 토큰을 임의로
   회수하지 않는다. PROVIDER의 트랜잭션과 고유 인덱스가 교체·소비를 직렬화한다.
   여러 연결의 경쟁에서 한 요청만 성공한다는 실행 증거가 필요하다.

4. **진행 중인 작업을 무효화하지 않는 설계도 엄격할 수 있다.** 먼저 실행
   경계를 잠그면 회수가 진행 중 작업과 부딪히는 상황을 예방할 수 있다.
   다만 동일 에이전트의 동시 실행은 제한된다. 병렬성을 늘리려면 권한 주체와
   작업 격리 단위를 새로 정의해야 한다.

5. **Landlock은 권한 교체 장치가 아니다.** 기존 프로세스의 제한은 완화할 수
   없다. 한 워커에 허용 자원을 계속 추가하는 방식은 이 프로젝트의 목적과
   맞지 않는다. 호출마다 새 실행 프로세스를 만드는 비용을 감수했다.

6. **커널 권한과 함수 의미는 층위가 다르다.** TCP 포트 허용은 특정 호스트나
   GET만 허용한다는 뜻이 아니다. Landlock ABI 9의 포트·파일·UNIX 소켓 제한에
   PROVIDER의 정확한 정책, 고정 핸들러와 seccomp를 함께 사용해야 했다.

7. **API 호환성은 신뢰 확대가 아니다.** OpenAI·Anthropic·Gemini·MCP의 호출
   모양은 PROVIDER에서 정규화하되, 모두 같은 도구·자원 정책을 통과하게 했다.
   형식별 메타데이터가 인증을 덮어쓰거나 한 배치가 권한을 공유하지 않는다.
   실제 벤더 모델을 호출한 검증과 호출 양식 검증은 구분해야 한다.

8. **타임아웃은 이전 실행이 끝났다는 증거가 아니다.** 토큰이 만료되거나
   워커가 끊겼다고 실행 잠금을 풀면 이전 실행과 새 권한이 겹칠 수 있다.
   이 구현은 미완료 잠금을 재시작 뒤에도 유지한다. 자동 복구 편의성보다
   권한 중첩 방지를 우선했고, 복구 절차는 추후 별도 문제로 남겼다.

9. **정책 변경과 인증서 재등록도 토큰 수명 문제다.** 재시작 뒤 정책을
   줄였는데 예전 토큰을 그대로 받아들이는 문제를 발견했다. admission 때
   현재 정책으로 정확한 기능을 다시 계산한다. 토큰과 완료 권한도 원래
   인증서 지문에 묶어, 같은 ID를 새 인증서로 재등록해도 이전 작업을 가져올
   수 없게 했다. 공유 상태를 쓰는 PROVIDER는 동일 정책으로 운영해야 한다.

10. **좁은 권한에서 라이브러리의 숨은 의존성이 드러난다.** 처음 실제 DB
    실험은 실패했다. SQLite는 파일 디스크립터 0·1·2를 DB에 사용하지 않으며,
    표준 입출력이 닫혔으면 `/dev/null`을 열어 보완한다. 이를 커널이 거부했다.
    허용 경로를 넓히는 대신 제한 전에 표준 입출력을 안전하게 초기화했다.
    최소 권한 설계는 라이브러리의 평소 보이지 않던 동작을 학습하게 한다.

11. **읽기 전용과 불변 스냅샷도 다르다.** SQLite의 immutable 모드는 WAL을
    무시할 수 있다. 살아 있는 DB를 그대로 등록하면 최신 값이 빠지는 문제가
    생긴다. 이 버전은 불변 스냅샷만 받으며, WAL·journal 상태를 등록·발급·
    admission·실행 경계에서 확인한다. 라이브 서버 DB에는 전용 핸들러와
    DB 측 역할 제한이 필요하다.

12. **데이터와 식별자는 다르게 검증해야 한다.** 경로의 NUL은 위험하지만
    파일 내용의 NUL은 데이터일 수 있다. 처음에는 공통 문자열 검증이 이를
    혼동했다. 내용은 보존하고 경로만 엄격히 검사하도록 나눴으며, 실제
    write/read 왕복을 확인했다. JSON 이스케이프가 크기를 키우는 경우도
    발급 전에 거절해 사용할 수 없는 토큰이 만들어지지 않게 했다.

13. **프로세스를 나눴다는 사실만으로 메모리가 깨끗해지지 않는다.** fork는
    부모 힙을 복사한다. 환경과 파일 디스크립터를 제거하고 인증정보 경로를
    막아도 기존 메모리는 남는다. 10월 19일에는 이를 실제 실행 자식에서
    재현하고, 핸들러 실행 전 봉인된 내장 이미지를 exec하는 구조로 바꿨다.
    이전 부모 매핑이 사라지는 검증을 추가했다. 고정 핸들러와 런타임은
    여전히 신뢰하며, 물리 RAM과 이미 받은 모델 지식까지 소거하지 않는다.

14. **실패와 부작용은 함께 기록해야 한다.** 파일 쓰기 뒤 완료 통신이
    실패하면 결과는 실패일 수 있지만 파일 효과는 이미 존재할 수 있다.
    워커는 실행 성공 여부와 finish 오류를 구분해 반환하고, 이를 자동으로
    재실행하지 않는다. exactly-once admission과 외부 효과의 exactly-once는
    같은 보장이 아니다.

15. **작동하는 예제와 재사용 가능한 라이브러리는 다르다.** 저장소 안에서만
    돌아가는 것을 넘어서 설치된 CMake 타깃을 별도 프로젝트에서 링크하고,
    Python wheel을 소스 경로 밖에서 import했다. 소스 배포본에는 C++·문서·
    실험 코드를 포함하고, 실험 인증정보와 DB는 제외했다.

## 졸업프로젝트와 이력서에서 설명할 기여

“SAGA의 PROVIDER 개념을 확장하여 업무·함수·자원별 단일 사용 capability
프로토콜과 C++ 실행 워커를 구현했다. 인증서 기반 신원과 모델 출력을
분리하고, 트랜잭션 기반 회수·발행 및 Landlock ABI 9/seccomp 실행 제한을
실제 커널에서 검증했다.”

실제로 수행한 검증은 48개 Python 테스트, 2개 C++ 테스트, 외부 DB와 TLS
통합 실험, UBSan 및 설치 후 사용 검증이다. SAGA의 암호 프로토콜 전체를
재현했다거나 정형 증명을 확보했다는 표현은 이 구현의 근거와 다르다.

다음 연구 확장은 독립적인 주제가 될 수 있다: 검증 가능한 충돌 후 복구,
전용 서버 DB 핸들러, clean exec 격리, 다중 PROVIDER의 정책 세대 fencing,
정형 상태 모델, 실제 벤더 SDK 및 공격 데이터셋 기반 평가. 현재 버전의
일반적인 등록 정책 내부 자동 실행은 구현과 검증을 완료했다.
